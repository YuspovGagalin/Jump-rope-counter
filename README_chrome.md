1ファイル完結の Web アプリです。

## 最初に読んでください

> [!WARNING]
> **HTML ファイルをダブルクリックして開いても動きません。**

Google Chrome はセキュリティ上の理由で、次の場合に**カメラを完全に無効化**します。
これはブラウザ側の仕様で、アプリのコードでは回避できません。

- ファイルを直接開いた場合（アドレスが `file://` で始まる）
- `localhost` 以外のアドレスに `http://` でアクセスした場合

さらに `file://` では、骨格推定ライブラリ（MediaPipe）の読み込み自体も CORS で遮断されるため、
動画ファイルモードすら動作しません。

**対策は1つだけです。HTTPS または `localhost` で配信してください。**

| 使いたい環境 | 推奨する方法 |
|---|---|
| スマホの Chrome | [GitHub Pages で公開](#1-github-pages-で公開する推奨) |
| PC の Chrome | [`serve.py` で `localhost` 配信](#2-1-pc-の-chrome-で使う) |
| ネットに繋がない環境 | [`serve.py --https`](#方法a-servepy-の-https-モード) |

## 1. GitHub Pages で公開する（推奨）

このリポジトリをそのまま HTTPS で配信できます。証明書の警告も出ず、
スマホからも PC からも同じ URL で使えるため、最も手間がかかりません。

### 手順

1. リポジトリの **Settings** → 左メニューの **Pages** を開く
2. **Source** で `Deploy from a branch` を選ぶ
3. **Branch** を `main`、フォルダを `/ (root)` にして **Save**
4. 1〜2分待つと、ページ上部に公開 URL が表示される

    ```
    https://<ユーザー名>.github.io/<リポジトリ名>/
    ```

5. その URL の末尾にファイル名を付けて Chrome で開く

    ```
    https://<ユーザー名>.github.io/<リポジトリ名>/jump_rope_counter_rev5_chrome-support.html
    ```

> [!TIP]
> HTML ファイルを `index.html` にリネームしておくと、ファイル名なしの URL で開けるようになります。
> スマホで毎回入力する手間が減るので、イベントなどで使う場合はおすすめです。

> [!NOTE]
> リポジトリが Private の場合、GitHub Pages は有料プランでないと公開できません。
> Public にするか、[ローカルサーバー](#2-ローカルサーバーで使う)をお使いください。

## 2. ローカルサーバーで使う

ネットに公開したくない場合や、オフライン環境で使う場合はこちらです。
同梱の `serve.py` を使います。

### 事前準備

Python 3 が必要です。

| OS | 確認コマンド | 未インストールの場合 |
|---|---|---|
| Windows | `py --version` | Microsoft Store で「Python 3」を検索してインストール |
| Mac | `python3 --version` | 標準で入っています。無ければ `brew install python3` |

次の2つのファイルを**同じフォルダ**に置いてください。

- `jump_rope_counter_rev5_chrome-support.html`
- `serve.py`

### 2-1. PC の Chrome で使う

`localhost` は Chrome が例外的にカメラを許可するアドレスなので、HTTPS は不要です。

1. ファイルを置いたフォルダで、コマンドプロンプト（またはターミナル）を開く

    - **Windows:** フォルダのアドレスバーに `cmd` と入力して <kbd>Enter</kbd>
    - **Mac:** フォルダを右クリック →「フォルダに新規ターミナル」

2. 次のコマンドを実行する

    ```bash
    # Windows
    py serve.py

    # Mac
    python3 serve.py
    ```

3. Chrome が自動で開きます。開かない場合は http://localhost:8000/ にアクセス
4. 画面上部の「動作環境」が**緑色（問題ありません）**になっていることを確認する
5. 「カメラを開始」を押し、許可ダイアログで「許可」を選ぶ

終了するには、コマンドプロンプトで <kbd>Ctrl</kbd> + <kbd>C</kbd> を押してください。

### 2-2. スマホの Chrome で使う

スマホからは `localhost` の例外が使えない（スマホ自身を指してしまう）ため、**HTTPS が必須**です。

#### 方法A: `serve.py` の HTTPS モード

PC とスマホが**同じ Wi-Fi** につながっている必要があります。

1. PC で次のコマンドを実行する

    ```bash
    # Windows
    py serve.py --https

    # Mac
    python3 serve.py --https
    ```

2. 画面に表示される、スマホ用のアドレスを確認する

    ```
    同じWi-FiにつないだスマホのChromeから:
        https://192.168.1.5:8443/jump_rope_counter_rev5_chrome-support.html
    ```

3. そのアドレスをスマホの Chrome で開く
4. **「接続がプライベートではありません」という警告が出ます。**
   自己署名証明書を使っているためで、想定どおりの動作です。
   「詳細設定」→「(安全ではありません) にアクセスする」を選んでください
5. 「カメラを開始」を押し、許可ダイアログで「許可」を選ぶ

> [!NOTE]
> つながらない場合、PC のファイアウォールがポート 8443 を塞いでいる可能性があります。
> Windows Defender ファイアウォールの通知が出たら「アクセスを許可する」を選んでください。
> また、職場や学校の Wi-Fi では端末どうしの通信が禁止されている場合があります。

証明書は初回起動時に `localhost_cert.pem` と `localhost_key.pem` として作られ、
2回目以降は再利用されます。作り直したい場合はこの2つを削除してください。

> [!IMPORTANT]
> 生成される `*.pem` は秘密鍵を含みます。`.gitignore` に追加して、リポジトリにコミットしないでください。
>
> ```gitignore
> localhost_cert.pem
> localhost_key.pem
> ```

#### 方法B: Chrome のフラグで例外登録する（検証用）

Android の Chrome 限定です。証明書を用意せずに `http://` でカメラを使えるようにします。
**検証用の機能**なので、使い終わったら元に戻してください。

1. PC で `py serve.py`（HTTPS なし）を実行し、表示されたスマホ用アドレスを控える
   （例: `http://192.168.1.5:8000`）
2. Android の Chrome のアドレスバーに次を入力する

    ```
    chrome://flags/#unsafely-treat-insecure-origin-as-secure
    ```

3. 入力欄に控えたアドレスを**ポート番号まで**入力し、右のプルダウンを **Enabled** にする
4. 画面下部の「Relaunch」を押して Chrome を再起動する

## 3. 画面上部の「動作環境」の見方

アプリを開くと、最初に環境チェックの結果が表示されます。

| 表示 | 意味 | 対応 |
|---|---|---|
| 🟢 問題ありません | カメラを使える状態 | そのまま「カメラを開始」へ |
| 🟡 注意事項があります | 動作はするが推奨環境ではない | 「詳細」を開いて内容を確認 |
| 🔴 カメラを使えません | 表示方法かライブラリに問題がある | パネル内の対処法に従う |

チェックしている項目は次の5つです。

| 項目 | 内容 |
|---|---|
| ブラウザ | Chrome / Edge かどうか |
| 表示方法 | `file://` / `http://` / `https://` / `localhost` の判別 |
| セキュアコンテキスト | ブラウザがカメラ利用を許す状態か |
| カメラ API | `navigator.mediaDevices` が使えるか |
| MediaPipe | 骨格推定ライブラリを読み込めたか（インターネット接続が必要） |

## 4. 使い方

### 計測の流れ

```
全身が映っていない
  → 「カメラの前に立ってください」

全身を検出
  → 「3」→「2」→「1」   （この3秒間に地面の高さを学習します）

カウントダウン終了
  → 「スタート！」       ← この瞬間から計測開始
```

一定時間（初期値3秒）ジャンプも縄の通過も検知されないと、
カウントを 0 に戻して次の計測を始めます。直前の値は「前回の記録」として画面に残ります。

### カメラの設置

- 全身（頭から足元まで）と、足の周りの床が映る位置に置く
- 三脚や壁に立てかけて固定する
- 挑戦者は 2〜3 メートル離れる
- 赤色の検出は明るさに左右されるため、できるだけ明るい場所で使う

### 縄の検出がうまくいかないとき

1. 「赤色マスク表示」をオンにして、**縄だけが水色にハイライトされる**ように
   「赤の許容色相」と「赤の最低彩度」を調整する
2. グラフ下部のオレンジの実線（赤の検出量）の山が、
   オレンジの点線（しきい値）を明確に跨ぐように「通過判定しきい値」を調整する
3. 多く数えすぎる場合は「最小通過間隔」を上げる。高速な三重跳びで取りこぼす場合は下げる

## 5. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 「カメラを開始」を押しても何も起きない | 許可ダイアログを以前「ブロック」にした可能性があります。アドレスバー左の鍵アイコン →「サイトの設定」→ カメラを「許可」に変更し、ページを再読み込みしてください |
| 映像は出るが骨格の線が出ない | 全身が映っていません。カメラから 2〜3 メートル離れてください |
| 「他のアプリがカメラを使用中」と出る | Zoom、Teams、カメラアプリなどを終了してから再試行してください |
| スマホで動きがカクカクする | 「処理の重さ」を**軽量**、解像度を**低**、「判定グラフを表示」を**オフ**にしてください |
| 縄が数えられない | 「赤色マスク表示」をオンにして色相・彩度を調整してください。暗い場所では検出が不安定になります |
| 証明書の警告が消えない | 自己署名証明書では毎回警告が出ます。気になる場合は GitHub Pages をお使いください |
| MediaPipe が読み込めない | CDN（`cdn.jsdelivr.net`）への接続が必要です。オフラインや社内ネットワークの制限下では動作しません |

## 6. serve.py のオプション

| コマンド | 動作 |
|---|---|
| `python3 serve.py` | HTTP で起動（ポート 8000）。PC の Chrome 用 |
| `python3 serve.py --https` | HTTPS で起動（ポート 8443）。自己署名証明書を自動生成。スマホ用 |
| `python3 serve.py --port 9000` | ポート番号を変更する |
| `python3 serve.py --no-open` | ブラウザを自動で開かない |

Windows では `python3` の代わりに `py` を使ってください。

## 技術メモ

- **ジャンプ判定:** MediaPipe Pose の足首・腰のランドマークから平均高さを求め、
  胴の長さに対する比率でしきい値を動的に決める。着地時にカウント
- **縄跳び判定:** 足元の検出ゾーン内の赤色画素の面積率を HSV で求め、
  しきい値を下から上へ跨いだ回数をカウント。常時写り込む赤（服・靴・背景）は
  ベースラインとして自動学習し差し引く
- **依存:** MediaPipe Pose / Drawing Utils（CDN 経由）。ビルド不要の単一 HTML ファイル
